# Мок-интервью: Python (30 вопросов) — расширенные ответы

---

## Q1. Что такое GIL? Как его обойти?

**Ответ:**
GIL (Global Interpreter Lock) — блокировка в CPython, разрешающая только одному потоку исполнять байткод одновременно. Защищает внутренние структуры CPython от гонок ценой отсутствия параллелизма для CPU-bound в потоках.

**Обход:**
- **I/O-bound** → asyncio (корутины не блокируют GIL на I/O)
- **CPU-bound** → multiprocessing (каждый процесс — свой GIL)
- **Смешанное** → asyncio + `ProcessPoolExecutor`
- **C-расширения** (numpy, pandas) — отпускают GIL через `Py_BEGIN_ALLOW_THREADS`

## Q2. `__new__` vs `__init__`?

`__new__` — создаёт объект (вызывается ДО `__init__`), возвращает экземпляр.
`__init__` — инициализирует поля, не возвращает ничего.

**Где переопределять:** Singleton (один экземпляр на класс), кастомные метаклассы, неизменяемые типы (int/str/tuple — `__init__` не вызывается).

---

## Q3. Как работает MRO?

MRO = Method Resolution Order = C3 Linearization. Определяет порядок поиска методов при множественном наследовании. Правила: ребёнок раньше родителей, порядок в `class D(B, C)` соблюдается, общий предок — один раз.

**Пример:** `D(B, C)` где B и C наследуют A → MRO = `[D, B, C, A, object]`. `super()` идёт по MRO.

---

## Q4. async/await — как работает?

`async def` создаёт корутину. `await` — точка приостановки: корутина отдаёт управление event loop и ждёт результат. Event loop использует epoll/kqueue/IOCP для неблокирующего I/O. Ключевые функции: `gather`, `create_task`, `wait_for`, `as_completed`.

**Важно:** внутри `async def` нельзя `time.sleep()` или `requests.get()` — блокирует event loop.

---

## Q5. Декоратор — что возвращает?

Декоратор — callable, принимающий функцию и возвращающий новую (с доп. поведением). `@decorator` ≡ `func = decorator(func)`. `@functools.wraps` — обязателен (сохраняет `__name__`, `__doc__`). Для декоратора с аргументами — 3 уровня вложенности.

---

## Q6. Контекстный менеджер?

Объект/функция, гарантирующая cleanup ресурса (БД, файл, блокировка). Два способа: класс с `__enter__`/`__exit__` или `@contextmanager` с одним `yield`. `__exit__` получает информацию об исключении — может подавить (вернуть True) или пробросить.

---

## Q7. Mutable default — почему баг?

Дефолтные значения вычисляются один раз при определении функции (compile-time) и хранятся в `func.__defaults__`. Для mutable-типов (list, dict) все вызовы разделяют один объект.

**Фикс:** `def f(x=None): if x is None: x = []`

---

## Q8. `str` vs `repr`?

`__str__` — для пользователя (print, str()), читаемый. `__repr__` — для разработчика (repr(), отладка), точный: `eval(repr(obj))` должен создавать такой же объект. Если определён только `__repr__` — `__str__` использует его.

---

## Q9. `with open()` — как работает?

`with` вызывает `__enter__` → открывает файл, возвращает дескриптор. При выходе — `__exit__` → закрывает файл. Даже при исключении внутри блока `__exit__` вызывается (получает тип, значение, traceback).

---

## Q10. Что такое `typing.Protocol`?

Утиная типизация для статической проверки. Protocol определяет интерфейс (сигнатуры). Любой объект с этими сигнатурами удовлетворяет протоколу **без наследования** — structural subtyping. Проверяется на уровне mypy/pyright. В отличие от ABC не требует явного наследования.

---

## Q11. Как работает сборщик мусора?

**Reference counting (основной):** каждый объект хранит счётчик ссылок. Когда 0 → удаляется немедленно. **GC (вспомогательный):** generational GC для циклических ссылок. Три поколения: gen0 (новые), gen1, gen2 (долгоживущие). `gc.collect()` — ручной запуск.

---

## Q12. Что такое генератор? yield vs return?

Генератор — функция с `yield`. Сохраняет состояние между вызовами. `yield` — приостановка (next/send возобновляют). `return` — завершение генератора (и опционально значение в StopIteration с Python 3.3+).

---

## Q13. Как работает `list` внутри?

Динамический массив указателей на PyObject. При добавлении: если места нет — перевыделение с запасом (~12.5% рост). `append()` — O(1) амортизированно. `insert(0, x)` — O(n) (сдвиг).

---

## Q14. Что такое `async for`?

Асинхронный итератор: `__aiter__` + `__anext__`. Внутри `__anext__` можно делать `await`. Используется для асинхронных генераторов (yield внутри `async def`) и async-клиентов (постраничное чтение API).

---

## Q15. Что такое `__slots__`?

Ограничивает набор атрибутов экземпляра класса. Вместо `__dict__` создаётся массив фиксированного размера. Экономит память (~50%) и ускоряет доступ к атрибутам.

---

## Q16. `functools.partial` — зачем?

Фиксация части аргументов функции. Создаёт новый callable с предустановленными значениями. Удобно для преконфигурации: `fetch_fast = partial(fetch, timeout=5, retries=3)`.

---

## Q17. `try/except/else/finally` — порядок?

`try` → если исключение → `except` (подходящий) → если нет исключения → `else` → всегда → `finally`.

---

## Q18. `copy` vs `deepcopy`?

`copy.copy` — shallow: копирует объект, но внутренние ссылки — те же.
`copy.deepcopy` — рекурсивно копирует всё дерево объектов.

---

## Q19. Что такое `contextvars`?

Контекстные переменные — аналог thread-local, но работают с asyncio. Каждая корутина видит своё значение, даже если они работают в одном потоке. Используется для request_id, пользователя, трассировки.

---

## Q20. Как работает хэш-таблица в dict?

Массив слотов. Ключ → `hash(key)` → индекс слота. При коллизии — открытая адресация (линейный пробинг). Заполненность > 2/3 → перехэширование с удвоением размера. В Python 3.6+ порядок вставки сохраняется (компактная имплементация).

---

## Q21. Что такое `dataclass` и зачем?

Генерирует `__init__`, `__repr__`, `__eq__` (и опционально `__hash__`, order, frozen, slots). Экономит boilerplate для DTO. Параметры: `frozen=True` (immutable), `slots=True` (экономия памяти), `kw_only=True` (keyword-only поля).

---

## Q22. Что такое `@staticmethod` vs `@classmethod`?

`@staticmethod` — обычная функция внутри класса, нет доступа к `cls`/`self`.
`@classmethod` — получает `cls` как первый аргумент. Используется для фабричных методов и альтернативных конструкторов.

---

## Q23. Что делает `with suppress(Exception)`?

`contextlib.suppress` — контекстный менеджер, подавляющий указанные исключения. Аналог `try/except: pass`. Полезно для необязательного удаления: `with suppress(FileNotFoundError): os.remove(path)`.

---

## Q24. `async with` — как работает?

Вызывает `__aenter__` (может делать await) → возвращает ресурс → при выходе `__aexit__` (может делать await). Используется для async-ресурсов: `AsyncSession`, `httpx.AsyncClient`.

---

## Q25. `TypeVar` — что и зачем?

Переменная типа для Generic-классов/функций. `T = TypeVar("T", bound=Base)` — ограничение сверху. `T = TypeVar("T", str, int)` — только указанные типы. Используется с `Generic[T]`.

---

## Q26. Чем `asyncio.gather` отличается от `asyncio.wait`?

`gather` — принимает распакованные корутины, возвращает результаты списком. `return_exceptions=True` — ошибки как значения.
`wait` — принимает Tasks, возвращает `(done, pending)`, гибкая настройка (FIRST_COMPLETED, FIRST_EXCEPTION).

---

## Q27. `asyncio.TaskGroup` (Python 3.11+) — зачем?

Structured concurrency. Все задачи в группе: если одна падает — остальные отменяются. Гарантирует, что после выхода из `async with TaskGroup() as tg` все задачи завершены.

---

## Q28. `RuntimeError: This event loop is already running`?

Вызвали `asyncio.run()` внутри уже запущенного event loop (например, в Jupyter или внутри async-функции). Фикс: используйте `await` вместо `asyncio.run()`.

---

## Q29. `ConnectionResetError` при частых запросах?

Сервер закрыл соединение (keep-alive истек, перегрузка). Решение: connection pool + retry + exponential backoff. В httpx: `limits=Limits(max_keepalive_connections=20)`.

---

## Q30. Как отменить выполняющуюся корутину?

`task.cancel()` — выбрасывает `CancelledError` в точке await корутины. Корутина должна поймать и сделать cleanup. `asyncio.wait_for(task, timeout)` — автоматическая отмена по таймауту.
