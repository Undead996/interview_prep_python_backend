## Q1. Что такое GIL? Как его обойти?

```
✅ Ответ:
GIL — Global Interpreter Lock. Это блокировка в CPython, которая позволяет
исполнять байткод только одному потоку. Она защищает внутренние структуры
от гонок, но мешает CPU-bound параллелизму.

Как обойти:
- Для I/O-bound задач: asyncio (корутины не блокируют GIL на I/O)
- Для CPU-bound задач: multiprocessing (каждый процесс — свой GIL)
- Для смешанных: asyncio + ProcessPoolExecutor

GIL не затрагивает I/O (сеть, диск) — threading для I/O-bound работает.
```

## Q2. Разница между `__init__` и `__new__`?

```
✅ Ответ:
__new__ создаёт объект (вызывается до __init__). Он возвращает экземпляр.
__init__ — инициализирует поля, не возвращает ничего.

__new__ используется:
- В синглтонах (один экземпляр на класс)
- В кастомных метаклассах
- Для неизменяемых типов (int, str, tuple) — __init__ не вызывается

Пример синглтона:

class Singleton:
    _instance = None
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
```

## Q3. Как работает MRO?

```
✅ Ответ:
MRO — Method Resolution Order (C3 linearization). Python строит линейный
порядок классов, в котором ищутся методы.

Правила:
1. Ребёнок имеет приоритет над родителем
2. Порядок указания родителей в class D(B, C) влияет
3. Ни один класс не проверяется дважды

D(B, C) → MRO = [D, B, C, A, object] если B и C наследуют A.

super() следует MRO — это важно для кооперативного наследования.
```

## Q4. async/await — как это работает?

```
✅ Ответ:
async def создаёт корутину. await — точка приостановки: корутина отдаёт
управление event loop'у и ждёт, пока результат будет готов. Event loop
переключается на следующую корутину.

Ключевые функции:
- asyncio.gather — конкурентный запуск всех задач
- asyncio.create_task — запуск в фоне
- asyncio.wait_for — таймаут

Важно: внутри async def нельзя делать time.sleep() или requests.get() —
это блокирует весь event loop!
```

## Q5. Декоратор — что возвращает?

```
✅ Ответ:
Декоратор — это функция (или класс), которая принимает другую функцию
и возвращает новую (с дополнительной логикой).

@decorator = decorator(func)

@functools.wraps(func) — ОБЯЗАТЕЛЕН! Без него теряются __name__ и __doc__.

Может быть классом с __call__ — для хранения состояния.
```

## Q6. Что такое контекстный менеджер?

```
✅ Ответ:
Объект с методами __enter__ (вызывается при входе в with) и __exit__
(вызывается при выходе, даже при исключении). Используется для управления
ресурсами — файлы, БД, блокировки.

Есть два способа:
1. Класс с __enter__ / __exit__
2. @contextmanager с yield

with DatabaseSession() as conn:
    conn.execute("...")
# Гарантированно закроет даже при ошибке
```

## Q7. mutable vs immutable — что с default?

```
✅ Ответ:
Mutable default — классический баг Python. Список в default создаётся
один раз при определении функции.

def f(x=[]):  # ❌ баг — список общий для всех вызовов
def f(x=None): if x is None: x = []  # ✅ правильно

Для dataclasses: field(default_factory=list)
```

## Q8. str vs repr?

```
✅ Ответ:
__str__ — для пользователя (print, str(obj)). Должен быть читаемым.
__repr__ — для разработчика (repr(obj), отладка). Должен быть точным:
eval(repr(obj)) должен создавать такой же объект.

Если определён только __repr__, __str__ использует его.
```

## Q9. Как работает `with open()`?

```
✅ Ответ:
with вызывает __enter__ → открывает файл, возвращает дескриптор.
При выходе из with — __exit__ → закрывает файл (close()).
Даже если внутри with произошло исключение, __exit__ вызывается
(и получает тип, значение, traceback).
```

## Q10. Что такое typing.Protocol?

```
✅ Ответ:
Утиная типизация для статической проверки. Protocol определяет интерфейс
(набор методов/атрибутов). Любой объект с этими методами удовлетворяет
протоколу — без наследования.

В отличие от ABC (Abstract Base Class), Protocol не требует явного
наследования — только совпадения сигнатуры. Проверка — на уровне mypy.
```
