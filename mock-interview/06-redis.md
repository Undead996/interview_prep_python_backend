# Мок-интервью: Redis (15 вопросов)

---

## Q1. Какие структуры данных в Redis?

```
✅ Ответ: «Strings (кэш, счётчики), Lists (очереди/стеки), Sets (уникальные),
Hashes (объекты), Sorted Sets (рейтинги, rate limiting), Streams (надёжные
очереди), HyperLogLog (приблизительный подсчёт уникальных), Bitmaps.»
```

## Q2. TTL — что происходит, когда истекает?

```
✅ Ответ: «Пассивно: при попытке чтения ключа — проверка, истек → удалён.
Активно: Redis каждые 100ms сканирует часть expired-ключей (random).
Настраивается: hz (default 10). Не используйте 1ms TTL — нагрузка.»
```

## Q3. Redis как очередь — List vs Streams?

```
✅ Ответ: «List (LPUSH/RPOP) — простая очередь, без гарантий.
Streams (XADD/XREADGROUP) — надёжная очередь, consumer groups,
ack, блокирующее чтение. Для продакшена — Streams. Для демо — List.»
```

## Q4. Redis persistence — RDB vs AOF?

```
✅ Ответ: «RDB — снэпшот, компактный, быстрый старт, потеря последнего
снэпшота. AOF — лог, потеря последней секунды, больше места.
На проде — оба: RDB для бэкапа, AOF для восстановления.»
```

## Q5. Sentinel vs Cluster?

```
✅ Ответ: «Sentinel — HA (failover master → replica). Cluster — шардирование
(16384 слотов) + HA. Sentinel — для одной инстанции. Cluster —
для больших объёмов (данные не помещаются на одной ноде).»
```

## Q6. Как инвалидировать кэш?

```
✅ Ответ: «TTL — автоматически. DEL при изменении данных (cache aside).
Versioned keys (user:v2:42). Write through — обновление в одной
транзакции. Write behind — асинхронно, риск stale read.»
```
