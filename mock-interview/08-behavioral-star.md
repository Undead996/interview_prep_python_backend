# Мок-интервью: STAR-заготовки

Подготовь 3 истории по 2 минуты. Используй STAR.

## История 1. Сложный баг

**Situation:** После деплоя пользователи не получали email-уведомления.
**Task:** Найти причину — тестовый стенд работал.
**Action:** Посмотрел логи RabbitMQ → сообщения уходят, но consumer не ack.
Consumer падал с таймаутом при отправке email. На тестовом — другой email-провайдер
с быстрым ответом.
**Result:** Увеличил timeout, добавил retry 3 раза, DLX для упавших.
Написал тест на таймаут.

## История 2. Инициатива

**Situation:** Тесты запускались только локально.
**Task:** Внедрить CI/CD с автотестами.
**Action:** Настроил GitHub Actions, TestClient + pytest, docker-compose для
тестового окружения.
**Result:** Баги стали находить за 1 час до PR, а не за 2 дня до релиза.

## История 3. Конфликт

**Situation:** Разработчик не хотел писать тесты — «это QA работа».
**Task:** Убедить, что тесты — ответственность разработчика.
**Action:** Показал, что тест на бизнес-логику ловит баги, которые QA
не видит до деплоя. Предложил писать unit-тесты на новые фичи.
Первые 2 спринта — ревью тестов вместе.
**Result:** Через месяц — 80% покрытия нового кода. Разработчик сам пишет тесты.
